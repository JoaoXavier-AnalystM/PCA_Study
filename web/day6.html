2. Como Analisar os Erros — Método Sistemático

Depois de cada simulado, não pule direto para o próximo. Use este método:

PassoO que fazerObjetivo
1. Classificar errosSepare os erros por domínio: PromQL, Fundamentos, Observability, Alerting, InstrumentaçãoIdentificar qual domínio precisa de mais estudo
2. Erro conceitual vs bobeiraDiferencie: "não sabia o conceito" vs "li errado" vs "esqueci um detalhe"Saber se precisa revisar ou apenas mais atenção
3. Revisão focadaPara cada erro conceitual, volte no material do dia correspondente e estude aquele tópicoCorrigir lacunas reais de conhecimento
4. Criar flashcards mentaisPara conceitos que errou, crie um mnemônico ou exemplo para fixarMemorização ativa
5. Refazer a questão1 hora depois, tente resolver a questão novamente sem ver a respostaValidar que entendeu o conceito
⚠️ Armadilhas Comuns nos Simulados

1. Confundir rate() e irate() — rate() usa toda a janela; irate() só os 2 últimos pontos
2. Esquecer o label "le" em histogram_quantile() — sempre precisa no by()
3. Trocar delta() e increase() — delta() é para Gauge; increase() é para Counter
4. Confundir by() e without() — by() mantém; without() remove
5. Errar as portas — 9090, 9091, 9093, 9100, 3000 (decore AGORA)
6. Naming convention — _total para counter, _seconds para tempo, snake_case sempre
7. Silence vs Inhibition — silence é manual; inhibition é automático via regra
8. Labels vs Annotations — labels para roteamento; annotations para humanos

3. Checklist de Revisão Rápida — Use Antes de Cada Simulado

PromQL (28% da prova)

  • rate() para counters, delta() para gauges
  • histogram_quantile() sempre com label "le"
  • by() mantém labels; without() remove
  • Regex em =~ é ancorada (^ e $ implícitos)
  • absent() retorna 1 se métrica ausente
  • predict_linear() para alertas preditivos
  • group_left/right para joins many-to-one

Fundamentos (20%)

  • Portas: 9090, 9091, 9093, 9100, 3000
  • Counter só sobe; Gauge sobe e desce
  • Histogram: _bucket, _sum, _count
  • Histogram vs Summary: server vs client
  • Naming: namespace_subsystem_name_unit
  • Alta cardinality = problema (user_id é proibido)

Observability (18%)

  • SLI = métrica medida; SLO = meta; SLA = contrato
  • Error Budget = 100% - SLO
  • Pull = Prometheus scrapa; Push = Pushgateway
  • Métricas vs Logs vs Traces (quando usar cada)
  • Service Discovery: K8s, Consul, EC2, file

Alerting (18%)

  • 3 estados: inactive, pending, firing
  • for: tempo em pending antes de firing
  • labels = roteamento; annotations = info
  • group_wait, group_interval, repeat_interval
  • Silence = manual; Inhibition = automático

Instrumentação (16%)

  • Client libs oficiais: Go, Java, Python, Ruby
  • Node Exporter = host OS; cAdvisor = containers
  • Blackbox = probes externos (HTTP, TCP, ICMP)
  • Pushgateway = batch jobs curtos
  • relabel_configs = antes scrape; metric_relabel = após
