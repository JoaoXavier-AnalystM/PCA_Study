2. How to Analyze Mistakes - Systematic Method

After each mock exam, do not jump straight to the next one. Use this method:

StepWhat to doGoal
1. Classify mistakesSplit the mistakes by domain: PromQL, Fundamentals, Observability, Alerting, InstrumentationIdentify which domain needs more study
2. Conceptual error vs careless mistakeTell apart: "didn't know the concept" vs "read it wrong" vs "forgot a detail"Know whether you need to review or just pay more attention
3. Focused reviewFor each conceptual mistake, go back to that day's material and study the topicFix real knowledge gaps
4. Create mental flashcardsFor concepts you got wrong, create a mnemonic or an example to cement themActive memorization
5. Redo the question1 hour later, try to solve the question again without looking at the answerValidate that you understood the concept
⚠️ Common Traps in Mock Exams

1. Mixing up rate() and irate() - rate() uses the whole window; irate() only the last 2 points
2. Forgetting the "le" label in histogram_quantile() - it always needs to be in the by()
3. Swapping delta() and increase() - delta() is for gauges; increase() is for counters
4. Mixing up by() and without() - by() keeps; without() removes
5. Getting the ports wrong - 9090, 9091, 9093, 9100, 3000 (memorize NOW)
6. Naming convention - _total for counters, _seconds for time, always snake_case
7. Silence vs Inhibition - silence is manual; inhibition is automatic via rule
8. Labels vs Annotations - labels for routing; annotations for humans

3. Quick Review Checklist - Use Before Each Mock Exam

PromQL (28% of the exam)

  • rate() for counters, delta() for gauges
  • histogram_quantile() always with the "le" label
  • by() keeps labels; without() removes
  • Regex in =~ is anchored (implicit ^ and $)
  • absent() returns 1 if the metric is missing
  • predict_linear() for predictive alerts
  • group_left/right for many-to-one joins

Fundamentals (20%)

  • Ports: 9090, 9091, 9093, 9100, 3000
  • Counter only goes up; Gauge goes up and down
  • Histogram: _bucket, _sum, _count
  • Histogram vs Summary: server vs client
  • Naming: namespace_subsystem_name_unit
  • High cardinality = problem (user_id is forbidden)

Observability (18%)

  • SLI = measured metric; SLO = target; SLA = contract
  • Error Budget = 100% - SLO
  • Pull = Prometheus scrapes; Push = Pushgateway
  • Metrics vs Logs vs Traces (when to use each)
  • Service Discovery: K8s, Consul, EC2, file

Alerting (18%)

  • 3 states: inactive, pending, firing
  • for: time in pending before firing
  • labels = routing; annotations = info
  • group_wait, group_interval, repeat_interval
  • Silence = manual; Inhibition = automatic

Instrumentation (16%)

  • Official client libraries: Go, Java, Python, Ruby
  • Node Exporter = host OS; cAdvisor = containers
  • Blackbox = external probes (HTTP, TCP, ICMP)
  • Pushgateway = short batch jobs
  • relabel_configs = before scrape; metric_relabel = after
