1. Client Libraries - Instrumentando sua Aplicação

Client libraries permitem que sua aplicação exponha métricas diretamente no formato Prometheus através de um endpoint /metrics.

Para a Prova

As 4 linguagens com client libraries oficiais são: Go, Java, Python e Ruby. PHP e outras não são oficiais.

Exemplo de instrumentação em Python

from prometheus_client import Counter, Gauge, Histogram, start_http_server
import time

# Counter - só sobe
REQUEST_COUNT = Counter(
    'http_requests_total',
    'Total de requisições HTTP',
    ['method', 'endpoint', 'status_code']  # labels
)

# Gauge - sobe e desce
ACTIVE_CONNECTIONS = Gauge(
    'active_connections',
    'Número atual de conexões ativas'
)

# Histogram - distribui em buckets
REQUEST_LATENCY = Histogram(
    'http_request_duration_seconds',
    'Latência das requisições HTTP',
    buckets=[0.01, 0.05, 0.1, 0.5, 1.0, 5.0]  # le values
)

# Uso
REQUEST_COUNT.labels(method='GET', endpoint='/api', status_code='200').inc()
ACTIVE_CONNECTIONS.set(42)
ACTIVE_CONNECTIONS.inc()      # +1
ACTIVE_CONNECTIONS.dec()      # -1

with REQUEST_LATENCY.time():  # mede o tempo automaticamente
    do_request()

# Subir o servidor de métricas na porta 8000
start_http_server(8000)
# Acesse: http://localhost:8000/metrics

2. Naming Convention para Métricas

Seguir a naming convention é cobrado na prova e mantém as métricas consistentes.

Formato geral
namespace_subsystem_name_unit em snake_case
namespace
Nome da aplicação ou empresa. Ex: myapp, http, node
subsystem
Componente interno. Ex: database, cache, api
name
O que está sendo medido. Ex: requests, errors
unit
Unidade de medida. Ex: seconds, bytes, total
SufixoTipoExemploNunca usar
_totalCounterhttp_requests_total_count (reservado para Histogram)
_secondsDuraçãohttp_request_duration_seconds_ms, _secs (use SI)
_bytesTamanhohttp_response_size_bytes_kb, _mb
_ratioProporçãodisk_usage_ratioPorcentagem (use 0-1)
_infoGauge para metadataprocess_infoMisturar com métricas reais
🚫 Erros de Naming

❌ latencyMs → ✅ http_request_duration_seconds
❌ cpu_percent → ✅ cpu_utilization_ratio (0-1) ou sem sufixo
❌ requests → ✅ http_requests_total (sempre prefixo descritivo)
❌ http_request_duration_ms → ✅ usar segundos (unidade SI)

3. Principais Exporters

Node Exporter - Métricas de Host

Porta
:9100
Coleta
CPU, memória, disco, rede, filesystem, processos do sistema operacional
Onde roda
Direto no host (não em container) para acesso ao kernel
Métricas principais
node_cpu_seconds_total, node_memory_MemAvailable_bytes, node_filesystem_avail_bytes, node_network_receive_bytes_total
# Uso de CPU por modo (idle, user, system, iowait...)
node_cpu_seconds_total{cpu="0", mode="idle"}

# CPU usage %
100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# Memória disponível em MB
node_memory_MemAvailable_bytes / 1024 / 1024

# Disco livre %
node_filesystem_avail_bytes / node_filesystem_size_bytes * 100

cAdvisor - Métricas de Containers

Porta
:8080
Coleta
CPU, memória, rede e I/O de cada container Docker/Kubernetes
No Kubernetes
Já integrado ao kubelet - não precisa instalar separadamente
Métricas principais
container_cpu_usage_seconds_total, container_memory_usage_bytes, container_network_receive_bytes_total

Blackbox Exporter - Monitoramento Externo

Função
Faz probes de endpoints como um usuário externo: HTTP, TCP, ICMP, DNS
Casos de uso
Verificar disponibilidade, checar SSL expiration, testar conectividade
Diferencial
Testa de fora - complementa métricas internas da aplicação
# prometheus.yml - configuração do Blackbox Exporter
scrape_configs:
  - job_name: 'blackbox'
    metrics_path: /probe        # endpoint especial do blackbox
    params:
      module: [http_2xx]        # qual módulo usar
    static_configs:
      - targets:
          - https://example.com
          - https://api.myapp.com/health
    relabel_configs:
      - source_labels: [__address__]
        target_label: __param_target
      - source_labels: [__param_target]
        target_label: instance
      - target_label: __address__
        replacement: blackbox-exporter:9115  # endereço do exporter

Pushgateway - Para Batch Jobs

Porta
:9091
Função
Buffer para jobs que terminam antes do próximo scrape
API Push
PUT /metrics/job/{jobname}/instance/{instance}
API Delete
DELETE /metrics/job/{jobname}
Persistência
Métricas ficam até serem deletadas manualmente - não expiram
Quando NÃO usar
Para serviços de longa duração - use scrape direto
# Exemplo: batch job faz push e deleta métricas ao terminar (shell)
# Push das métricas
echo "batch_job_duration_seconds 12.5" | \
  curl --data-binary @- http://pushgateway:9091/metrics/job/backup_job/instance/server1

# Push com múltiplas métricas
cat << EOF | curl --data-binary @- http://pushgateway:9091/metrics/job/my_batch
# TYPE batch_job_duration_seconds gauge
batch_job_duration_seconds 42.0
# TYPE batch_job_records_processed_total counter
batch_job_records_processed_total 1500
EOF

# Deletar após conclusão (IMPORTANTE!)
curl -X DELETE http://pushgateway:9091/metrics/job/backup_job/instance/server1

4. Service Discovery e Relabeling

Como funciona o Service Discovery no Kubernetes

scrape_configs:
  - job_name: 'kubernetes-pods'
    kubernetes_sd_configs:
      - role: pod              # descobre todos os pods
    relabel_configs:
      # Mantém apenas pods com annotation prometheus.io/scrape: "true"
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: "true"
      # Usa a porta da annotation prometheus.io/port
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_port]
        action: replace
        target_label: __address__
        regex: (.+)
        replacement: $1
      # Copia o nome do namespace como label
      - source_labels: [__meta_kubernetes_namespace]
        target_label: namespace
      # Copia o nome do pod como label
      - source_labels: [__meta_kubernetes_pod_name]
        target_label: pod

Ações de relabeling

keep
Mantém séries onde o regex faz match. Descarta o resto.
drop
Remove séries onde o regex faz match.
replace
Substitui o valor de um label (ação padrão).
labelmap
Mapeia labels por regex - copia múltiplos de uma vez.
labeldrop
Remove labels que fazem match do regex.
labelkeep
Mantém apenas labels que fazem match do regex.
Labels Especiais de Service Discovery (__meta_*)

Quando o SD descobre targets, ele cria labels temporários prefixados com __meta_. Esses labels só existem durante o relabeling e são descartados depois. Use source_labels para lê-los e target_label para copiá-los como labels permanentes.

relabel_configs vs metric_relabel_configs

ConfiguraçãoQuando executaO que afeta
relabel_configsAntes do scrape - filtra targetsQuais targets serão scrapados
metric_relabel_configsApós o scrape - filtra métricasQuais séries serão armazenadas
scrape_configs:
  - job_name: 'myapp'
    static_configs:
      - targets: ['app:8080']
    # Executado ANTES do scrape - filtra targets
    relabel_configs:
      - source_labels: [__address__]
        regex: '.*:8080'
        action: keep

    # Executado APÓS o scrape - filtra métricas recebidas
    metric_relabel_configs:
      - source_labels: [__name__]
        regex: 'go_.*'          # descarta métricas internas do Go runtime
        action: drop

Questões de Revisão

Q1. Qual exporter coleta métricas de CPU, memória e disco do sistema operacional host?
A) cAdvisor
B) Blackbox Exporter
C) Node Exporter (:9100)
D) Pushgateway
✅ Resposta: C
Node Exporter roda no host (não container) e expõe métricas do sistema operacional: CPU, memória, disco, rede, filesystem. Porta padrão :9100.
Q2. Qual das linguagens NÃO tem uma client library oficial do Prometheus?
A) Go
B) Python
C) PHP
D) Ruby
✅ Resposta: C
As 4 client libraries oficiais são: Go, Java/JVM, Python e Ruby. PHP não tem biblioteca oficial - existem apenas implementações de terceiros.
Q3. Qual o nome correto para uma métrica que conta o total de erros de banco de dados?
A) dbErrors
B) database_error_count
C) myapp_database_errors_total
D) MYAPP.DATABASE.ERRORS.TOTAL
✅ Resposta: C
Naming convention: namespace_subsystem_name_unit em snake_case. Counters usam sufixo _total. myapp = namespace, database = subsystem, errors = nome, total = sufixo de counter.
Q4. O que acontece com as métricas no Pushgateway quando o batch job que as enviou termina?
A) São automaticamente deletadas após o TTL configurado
B) Permanecem disponíveis até serem explicitamente deletadas via API ou restart
C) São enviadas imediatamente ao Prometheus e então apagadas
D) Expiram após o próximo scrape do Prometheus
✅ Resposta: B
Pushgateway persiste métricas indefinidamente. O batch job DEVE deletar suas métricas após terminar (DELETE /metrics/job/{job}) - caso contrário, o Prometheus continuará vendo métricas "velhas" de um job que já terminou.
Q5. Qual a diferença entre relabel_configs e metric_relabel_configs?
A) relabel_configs é para Kubernetes; metric_relabel_configs é para static_configs
B) relabel_configs executa antes do scrape (filtra targets); metric_relabel_configs executa após (filtra métricas)
C) São equivalentes - apenas nomes diferentes
D) metric_relabel_configs só funciona com regex
✅ Resposta: B
relabel_configs: executado antes do scrape para decidir quais targets serão scrapados. metric_relabel_configs: executado após o scrape para filtrar ou transformar métricas recebidas antes de armazenar.
Q6. Para que serve o Blackbox Exporter?
A) Para monitorar aplicações "black box" sem acesso ao código fonte
B) Para fazer probes externos de HTTP, TCP, ICMP - verificando disponibilidade como um usuário externo
C) Para criptografar métricas em trânsito
D) Para substituir o Node Exporter em ambientes containerizados
✅ Resposta: B
Blackbox Exporter verifica endpoints externamente: faz requisições HTTP, conecta via TCP, faz ping ICMP. Complementa métricas internas - enquanto a app reporta métricas internas, o Blackbox testa se está acessível de fora.
Q7. Qual a ação de relabeling para MANTER apenas targets com uma annotation específica?
A) action: filter
B) action: keep
C) action: include
D) action: allow
✅ Resposta: B
action: keep mantém targets onde o source_label faz match do regex, descartando todos os outros. É o oposto de action: drop, que remove os que fazem match.
Q8. Qual exporter é recomendado para monitorar métricas de pods no Kubernetes sem instalação adicional?
A) Node Exporter
B) cAdvisor (já integrado ao kubelet)
C) Blackbox Exporter
D) kube-state-metrics
✅ Resposta: B
cAdvisor é integrado ao kubelet do Kubernetes - já está disponível em cada nó sem instalação extra. Expõe métricas de CPU, memória e rede de cada container. kube-state-metrics expõe estado dos objetos K8s (replicas, health), não métricas de recursos.
